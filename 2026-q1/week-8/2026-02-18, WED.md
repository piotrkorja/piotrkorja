# 🛰 SAP Monthly PPO Reports — Clean Spec (Fun Edition)

## 🎯 Goal

Generate **monthly SAP-compatible reports** for aviation / PPO logistics that:

- Show inventory at month-end
    
- Track movements (incoming / outgoing)
    
- Calculate valuation (UAH)
    
- Track serial + status changes
    
- Export cleanly (JSON / XML / Excel)
    
- Sync to SAP (or fail loudly and honestly)
    

---

# 🧱 Core Concept

We introduce 3 structural elements:

|Concept|Why It Exists|
|---|---|
|`equipment_items` enhancements|Track quantity + status|
|`equipment_status_histories`|Audit trail of changes|
|`monthly_sync_batches`|One approved batch per unit per month|

Lean. Traceable. SAP-friendly.

---

# 🗃 Data Model Summary

## 1️⃣ Equipment Items

Now tracks:

- `quantity`
    
- `current_status`
    
- `price`
    
- `serial_number` (if serialized)
    

### Allowed statuses (example)

```
operational
in_repair
damaged
expended
written_off
assigned
stored
```

👉 These must be enum-backed in Rails.

---

## 2️⃣ Equipment Status History

Every time status changes:

|Field|Meaning|
|---|---|
|equipment_item_id|What changed|
|status_to|New status|
|change_date|When|
|changed_by_id|Who|
|notes|Why|

This enables:

- Monthly diff calculation
    
- SAP movement classification
    
- Combat loss traceability
    

---

## 3️⃣ Monthly Sync Batch

One per:

```
(period_start, unit_id)
```

Stores:

- `ppo_summary` (JSONB)
    
- approval info
    
- SAP sync status
    
- export timestamp
    
- error details (if any)

# 💰 Valuation Logic

### Method: `simple_current_price`

```
quantity_on_hand × current_price
```

Pros:

- Simple
    
- Fast
    
- Prototype-ready
    
- SAP-compatible snapshot logic
    

Cons:

- Not true moving average
    
- No variance tracking
    

That’s fine for Phase 1.

# 🔁 Monthly Flow (Sergeant UX)

1. Month closes.
    
2. System aggregates:
    
    - Equipment
        
    - Status changes
        
    - Write-offs
        
3. Batch created (`pending`)
    
4. Sergeant reviews summary
    
5. Sergeant approves
    
6. Export generated
    
7. SAP sync triggered
    
8. Status = success / failed
    

---

# 🧠 Business Rules

### Rule 1

There can be only one batch per month per unit.

### Rule 2

Once SAP sync is successful → batch becomes immutable.

### Rule 3

If sync fails → must log error, allow retry.

### Rule 4

Status history drives movement logic.

# 🧪 UAT (User Acceptance Testing) Criteria

Now the important part.

This is what makes this production-grade.

---

## 🟢 UAT 1 — Monthly Batch Creation

**Given**

- A unit with equipment items
    
- Status changes recorded in February
    

**When**

- User generates batch for 2026-02-01
    

**Then**

- A new `monthly_sync_batch` is created
    
- It contains:
    
    - correct totals
        
    - correct valuation
        
    - correct status changes
        
- It is marked `pending`
    

✅ Pass criteria:

- Totals match manual SQL verification
    
- Only one batch exists for that month
    

---

## 🟢 UAT 2 — Valuation Accuracy

**Given**

- 10 batteries at 1000 UAH
    
- 5 FPV at 20000 UAH
    

**When**

- Batch generated
    

**Then**

- Total value = 10,000 + 100,000 = 110,000 UAH
    

✅ Pass criteria:

- No rounding issues
    
- Decimal precision preserved
    

---

## 🟢 UAT 3 — Status Change Detection

**Given**

- 3 items changed from operational → expended
    
- 2 items changed from operational → damaged
    

**When**

- Batch generated
    

**Then**

- `status_changes` shows:
    
    ```
    expended: 3
    damaged: 2
    ```
    

✅ Pass criteria:

- Derived only from history table
    
- No phantom changes
    

---

## 🟢 UAT 4 — Duplicate Protection

**Given**

- Batch already exists for 2026-02 + Unit A
    

**When**

- User tries to create another
    

**Then**

- System blocks it
    

✅ Pass criteria:

- DB unique index prevents duplicates
    
- Proper error message shown
    

---

## 🟢 UAT 5 — SAP Sync Tracking

**Given**

- Batch approved
    
- Sync attempted
    

**When**

- SAP responds success
    

**Then**

- `sap_status = success`
    
- `exported_at` is set
    

If failure:

- `sap_status = failed`
    
- `sap_error` contains message
    

✅ Pass criteria:

- Cannot mark as success manually
    
- Error is persisted
    

---

## 🟢 UAT 6 — Audit Trail Integrity

**Given**

- Status changed 3 times in a month
    

**When**

- Batch generated
    

**Then**

- Only final status counted for inventory
    
- All changes logged historically
    

✅ Pass criteria:

- History table contains full change chain
    
- No data loss
